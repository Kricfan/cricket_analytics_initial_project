The big picture

The project is a pipeline: data goes in at one end, gets cleaned and summarised step by step, and comes out as charts in your browser. Each file has one job and passes its result to the next.

data/t20_jsons/*.json 5,845 match files Every ball of every T20 international, from Cricsheet. → combined stats.py Combiner Adds up every ball into totals per player. → data/output/*.csv Clean tables One row per player, plus one row per player per match. → dashboard/*.py Dashboard Loads the tables, analyses them and draws the charts.

The combiner only needs to run once (or again when you download new matches). The dashboard runs every time you open it. Inside the dashboard, four files split the work:

FileIts one jobUses
data_loader.pyRead the CSV files into memorypandas
analysis.pyDo the maths: totals, averages, rankings, comparisonspandas, numpy
charts.pyTurn tables of numbers into chartsPlotly
app.pyLay out the page and connect the other threeStreamlit
Why split it up?

When something looks wrong you know where to look. A wrong number means analysis.py, a chart in the wrong colour means charts.py, and something in the wrong place on the page means app.py. This is called separation of concerns.

Python ideas you'll meet

These come up again and again in the project. Each one has a short example.

variable
A name for a value. runs = 4 stores 4 under the name runs.
function (def)
A named, reusable recipe. def safe_div(a, b): creates one; safe_div(10, 2) runs it. return hands the answer back.
docstring
The text in """triple quotes""" just under a def. It describes what the function does and has no effect on how it runs.
comment (#)
Everything after # on a line is a note for humans. Python ignores it.
dictionary {}
Labelled values: {"runs": 45, "balls": 30}. Read one with d["runs"]. The match files are giant nested dictionaries.
list []
An ordered collection: ["India", "Australia"]. teams[0] is the first item.
for loop
Repeat for each item: for ball in deliveries: runs the indented code once per ball.
if / elif / else
Run code only when something is true. if runs == 4: … elif runs == 6: …
+=
Add to what's already there. total += 4 is short for total = total + 4.
import
Bring in code from elsewhere: a package (import pandas as pd) or one of your own files (import analysis).
f-string
A string with values slotted in: f"{runs} runs" becomes "45 runs". {x:,} adds commas: 1,331,673.
constant
A variable in CAPITALS, like OUTPUT_DIR. By convention it's set once at the top of a file and never changed.
DataFrame
pandas' name for a table, like a spreadsheet in memory. df["runs"] is one column, called a Series.
groupby
Split a table into groups and summarise each one. "Total runs per player" is groupby("player_id")["runs"].sum().
@decorator
A line starting with @ above a function adds extra behaviour to it. @st.cache_data makes Streamlit remember the result.
None / NaN
"No value". Used where a number can't exist, such as the batting average of someone never dismissed.

Cricket rules in the code

Much of the code exists to apply the official scoring rules correctly. When something looks oddly specific, it's usually one of these:

TermRuleWhat the code does
WideDoesn't count as a ball faced or a legal ballSkips adding to balls_faced and balls_bowled
No-ballCounts as faced by the batter, but isn't a legal ball for the bowlerAdds to balls_faced but not balls_bowled
Byes / leg byesRuns for the team, not charged to the bowlerLeft out of runs_conceded
Run outA dismissal, but not the bowler's wicketListed in NOT_BOWLER_WICKETS
Retired hurtThe batter leaves but isn't outListed in NOT_OUT_KINDS
MaidenA full over by one bowler with no runs concededChecked at the end of each over
Super overTie-breaker; not included in official career statsSkipped entirely
Batting averageRuns ÷ times outruns / dismissals
Strike rateRuns per 100 balls facedruns / balls_faced × 100
EconomyRuns conceded per over (6 balls)runs_conceded / balls_bowled × 6

data/python files/combined stats.py

The combiner

In one sentenceReads all 5,845 match files ball by ball and adds everything up into clean stats for every player.
Think of it asA scorer going through every scorebook ever written and filling in one career card per player.

It runs as four stages, each its own function:

  1. process_match reads one match file and works out each player's stats for that match.
  2. build_players runs process_match on every file and adds the results into career totals.
  3. format_player turns raw totals into the tidy template (averages, strike rates, best figures).
  4. main runs the steps above and saves the three output files.

1. Rules written down once at the top

JSON_DIR = DATA_DIR / "t20_jsons"
OUTPUT_DIR = DATA_DIR / "output"

NOT_BOWLER_WICKETS = {
    "run out", "retired hurt", "retired out", "retired not out",
    "obstructing the field", "timed out", "handled the ball",
}
NOT_OUT_KINDS = {"retired hurt", "retired not out"}

Constants. Folder locations and cricket rules are written once here, so the rest of the code can just refer to them by name.

The / between paths joins folder names, like typing data\output.

The curly brackets make a set, a list that's quick to check with in.

2. A blank scorecard for each player

def new_match_line():
    """Blank stats for one player in one match."""
    return {
        "batted": False, "runs": 0, "balls_faced": 0,
        "fours": 0, "sixes": 0, "out": False,
        "balls_bowled": 0, "runs_conceded": 0, "wickets": 0,
        "catches": 0, "stumpings": 0, "run_outs": 0,
        # ... plus a few more counters
    }

Returns a fresh dictionary with every counter at zero, like an empty row on a scorecard.

Later the code uses defaultdict(new_match_line). That means: whenever a player we haven't seen yet is mentioned, automatically give them a blank scorecard.

3. Going through every ball

This is the heart of the project. A match file is nested: a match has innings, an innings has overs, an over has deliveries. So there's a loop inside a loop inside a loop.

Inside process_match(path)
with open(path, encoding="utf-8") as f:
    match = json.load(f)

Opens one match file and turns its JSON text into a Python dictionary called match.

for innings in match.get("innings", []):
    if innings.get("super_over"):
        continue  # super overs don't count

    for over in innings.get("overs", []):
        for ball in over.get("deliveries", []):

Three loops in a row: every innings, then every over in it, then every ball in that over.

continue means "skip the rest and move on to the next one". Super overs get skipped.

.get("innings", []) means "give me the innings, or an empty list if there aren't any", so a strange file can't crash the script.

batter, bowler = pid(ball["batter"]), pid(ball["bowler"])
runs, extras = ball["runs"], ball.get("extras", {})
is_wide, is_noball = "wides" in extras, "noballs" in extras
legal = not is_wide and not is_noball

Pulls out who batted, who bowled, and the runs.

pid() swaps the player's name for their unique ID. Two different players can share a name, but never an ID.

legal is True only for a proper delivery (not a wide, not a no-ball).

bat = lines[batter]
bat["runs"] += runs["batter"]
if not is_wide:
    bat["balls_faced"] += 1

Batting. Gets the batter's scorecard and adds the runs they hit.

The ball counts as faced unless it was a wide.

bowl = lines[bowler]
conceded = (runs["batter"] + extras.get("wides", 0)
            + extras.get("noballs", 0))
bowl["runs_conceded"] += conceded
if legal:
    bowl["balls_bowled"] += 1

Bowling. The bowler is charged for runs off the bat, wides and no-balls, but not byes or leg byes.

Only legal balls count towards their overs.

for wicket in ball.get("wickets", []):
    kind = wicket["kind"]
    out = lines[pid(wicket["player_out"])]
    if kind not in NOT_OUT_KINDS:
        out["out"] = True
    if kind not in NOT_BOWLER_WICKETS:
        bowl["wickets"] += 1

Wickets. If a wicket fell on this ball, mark the batter as out (unless they retired hurt), and credit the bowler (unless it was a run out or similar).

This is where the rule sets from the top of the file get used.

4. Adding matches into careers

Inside build_players(), shortened
files = sorted(JSON_DIR.glob("*.json"))

for i, path in enumerate(files, 1):
    try:
        match, lines, names = process_match(path)
    except (json.JSONDecodeError, KeyError) as e:
        print(f"  Skipping {path.name}: {e}")
        continue

glob("*.json") finds every file ending in .json.

try / except is a safety net. If one file is broken, it prints a message and carries on instead of stopping the whole run.

    for player_id, line in lines.items():
        p = players.setdefault(player_id, {...})
        for key in ("runs", "balls_faced", "wickets", ...):
            p["totals"][key] += line[key]

For each player in this match, find their career record (or create one with setdefault if this is their first match), then add this match's numbers onto their running totals.

5. The clean template

Inside format_player(p), shortened
def safe_div(a, b, digits=2):
    return round(a / b, digits) if b else None

Division that can't crash. Dividing by zero is an error in Python, so if b is 0 it returns None instead. A player who was never out has no batting average.

"batting": {
    "innings": p["innings_batted"],
    "runs": t["runs"],
    "average": safe_div(t["runs"], t["dismissals"]),
    "strike_rate": safe_div(t["runs"] * 100,
                            t["balls_faced"]),
    # ...
},
"bowling": { ... },
"fielding": { ... },

Builds the readable record you see in players_combined.json, grouped into batting, bowling and fielding.

Averages and rates are calculated here from the raw totals.

dashboard/data_loader.py

The data loader

In one sentenceOpens the two CSV files, tidies a few columns, and keeps them in memory so the dashboard stays fast.
Think of it asFetching the scorebooks from the shelf once and leaving them open on the desk.
@st.cache_data(show_spinner="Loading match data...")
def load_match_stats():
    matches = pd.read_csv(MATCH_STATS_FILE,
                          dtype={"match_id": str})
    matches = matches.dropna(subset=["team"])

@st.cache_data tells Streamlit to remember the result. Reading 129,000 rows takes a few seconds, so it happens once and is reused on every click.

pd.read_csv turns the CSV file into a DataFrame (a table).

dropna removes rows with no team. Those are substitute fielders who weren't in either starting XI.

    matches["date"] = pd.to_datetime(matches["date"])
    matches["year"] = matches["date"].dt.year
    matches["gender_label"] = matches["gender"].map(
        GENDER_LABELS)
    return matches

Adds helper columns. Text like "2017-02-17" becomes a real date, then a year column is pulled out of it for the yearly charts.

.map(GENDER_LABELS) swaps "male"/"female" for the friendlier "Men"/"Women".

load_career_stats() does the same for the career file. data_files_exist() checks that both files are there, so the app can show a helpful message if you forgot to run the combiner.

dashboard/analysis.py

The analysis

In one sentenceEvery calculation in the dashboard: filtering, totals, averages, rankings and comparisons.
Think of it asThe team analyst. Give them a table, ask a question, get a smaller table of answers back.

Every function here takes a table in and gives a table (or a few numbers) back. None of them draw anything. Keeping the maths separate means you could reuse it in a notebook or a different app.

Filtering with a mask

filter_matches(): applies the sidebar filters
first_year, last_year = year_range
mask = (
    matches["gender_label"].isin(genders)
    & matches["year"].between(first_year, last_year)
)
if teams:
    mask &= matches["team"].isin(teams)
return matches[mask]

A mask is a column of True/False, one per row: "does this row pass the filter?"

& means AND: the row must match the gender and the years.

matches[mask] keeps only the True rows. This is the most common pandas pattern you'll see.

Group, then summarise

yearly_trends(): powers the Overview charts
grouped = matches.groupby(["year", "gender_label"]).agg(
    matches=("match_id", "nunique"),
    runs=("runs", "sum"),
    balls=("balls_faced", "sum"),
    fours=("fours", "sum"),
    sixes=("sixes", "sum"),
).reset_index()

Puts rows into piles, one pile per year per gender (2016 Men, 2016 Women, …), then summarises each pile.

Each line reads as new_column=("old_column", "how"). For example, runs=("runs", "sum") means "add up the runs column".

nunique counts distinct values, which gives the number of matches.

grouped["strike_rate"] = safe_ratio(
    grouped["runs"], grouped["balls"], 100)

Works out a new column from existing ones, for every row at once. No loop needed: pandas does the whole column in one go.

Sorting batters into types

batter_archetypes(): the Batting tab's scatter chart
median_avg = qualified["average"].median()
median_sr = qualified["strike_rate"].median()

high_avg = qualified["average"] >= median_avg
high_sr = qualified["strike_rate"] >= median_sr

The median is the middle value: half of players are above it, half below. It's the "typical" batter.

high_avg and high_sr are True/False columns: is each batter above typical?

qualified["archetype"] = np.select(
    [high_avg & high_sr, high_avg, high_sr],
    ["Elite", "Anchor", "Aggressor"],
    default="Developing",
)

np.select is an if / elif / else for a whole column. It checks the conditions in order and uses the first label that matches:

both high → Elite; only average high → Anchor; only strike rate high → Aggressor; neither → Developing.

What wins matches?

team_innings() and match_winning_factors(): the Teams tab
per_team = matches.groupby(["match_id", "team"]).agg(
    gender=("gender_label", "first"),
    won=("team_won", "max"),
    top_score=("runs", "max"),
    best_wickets=("wickets", "max"),
).reset_index()

Shrinks 11 player rows into one row per team per match, recording whether they won, their top batter's score and their best bowler's wickets.

factors = {
    "A batter scores 50+": per_team["top_score"] >= 50,
    "A bowler takes 3+ wickets": per_team["best_wickets"] >= 3,
}

Then it compares win rates with and without each one. That's where the finding "teams with a half-centurion win 69% of the time, compared with 38%" comes from.

The other functions follow the same group-then-summarise pattern: aggregate_players (leaderboards), team_records (win rates), and the player_* functions for the Player tab (form over time, record against each opponent, how they get out, impact on wins).

Follow one number

Here's the journey of Virat Kohli's 3,963 career runs, from a single ball in a match file to the number on your screen.

  1. data/t20_jsons/<match>.json A ball in a match file records "batter": "V Kohli" and "runs": {"batter": 4}.
  2. combined stats.py → process_match() The ball loop runs bat["runs"] += runs["batter"], so Kohli's scorecard for that match goes up by 4. It also adds one to his fours.
  3. combined stats.py → build_players() Each match's runs are added onto his career total. After all 118 of his matches it reaches 3963.
  4. combined stats.py → main() The total is written to player_career_stats.csv in the batting_runs column, alongside his per-match rows in player_match_stats.csv.
  5. data_loader.py → load_career_stats() The dashboard reads the CSV into a table called career.
  6. app.py → Player tab You pick Kohli. The app finds his row with career[career["player_id"] == player_id] and shows profile["batting_runs"].
  7. your browser st.metric("Runs", ...) displays it as 3,963.

His charts follow a parallel route: player_match_stats.csv → analysis.player_innings() works out his running total and recent form → charts.player_form_chart() draws it.

Try it yourself

Each change is small and safe. Start the dashboard, make the edit, save the file, then click Rerun in the top-right corner of the dashboard to see the result. If something breaks, git can undo it: git checkout -- dashboard/app.py restores a file to its last commit.

1. Easy: change a starting value

The Batting tab starts with "Minimum innings to qualify" at 20. Make it start at 30.

Where: app.py, find st.slider("Minimum innings to qualify", 5, 100, 20,

Answer: the numbers are minimum, maximum, starting value. Change the last 20 to 30.

2. Easy: change a colour

Make the women's lines and bars purple instead of orange.

Where: charts.py, the line GENDER_COLOURS = {"Men": BLUE, "Women": ORANGE}

Answer: replace ORANGE with a colour code in quotes, such as "#9085e9". Every chart updates, because they all read from this one dictionary.

3. Medium: add a headline number

Add a seventh card to the Overview showing the total number of fours.

Step 1, in analysis.py: inside headline_kpis, add a line to the dictionary:

"fours": int(matches["fours"].sum()),

Step 2, in app.py: change st.columns(6) to st.columns(7), then add:

cols[6].metric("Fours", f"{kpis['fours']:,}")

Notice how the work splits: the number is calculated in analysis.py and displayed in app.py.

4. Harder: a new insight

Use the 💡 box to show who has hit the most sixes in the filtered period, on the Batting tab.

Check your understanding

Try to answer before opening each one.

Why is the combiner a separate script instead of part of the dashboard?

Reading 5,845 files ball by ball is slow. Doing it once and saving the results to CSV means the dashboard only has to load two ready-made tables, which takes seconds.

Players are tracked by ID, not name. Why?

Two different people can share a name, for example a men's and a women's player with the same initials and surname. IDs are unique, so their stats never get mixed together.

Which file would you change to make every chart taller?

charts.py, in the style_figure function. Its height=380 default is used by every chart.

You move the Seasons slider. What happens?

Streamlit reruns app.py from the top. The data comes from the cache, filter_matches builds a new mask for the new years, and every tab recalculates and redraws from the filtered table.

What does safe_div protect against?

Dividing by zero, which crashes Python. A batter who has never been dismissed would cause one when calculating their average, so it returns None instead.
